# Migrating to v1.0.0

## Migrating from v1.0.0-rc.4 to v1.0.0-rc.5

This candidate replaces authentication providers with guards and settles the module composition API
before v1.0.0. See RFCs [0002](../rfcs/0002-provider-factories-and-module-health.md),
[0003](../rfcs/0003-typed-module-configuration.md), [0004](../rfcs/0004-typed-request-state.md),
[0005](../rfcs/0005-guards.md), [0006](../rfcs/0006-typed-route-responses.md),
[0007](../rfcs/0007-error-diagnostics-and-default-status.md), and [0008](../rfcs/0008-serve.md).

- **Authentication uses guards.** Remove `jwtPlugin`/`oidcPlugin` from `plugins` and attach the
  guard to the groups or routes that need it. Replace `auth` with `guards`:

  | rc.4                                  | rc.5                                                          |
  | ------------------------------------- | ------------------------------------------------------------- |
  | `plugins: [jwtPlugin({ secret })]`    | `const auth = jwtBearer({ secret })` from `@hyapi/plugin-jwt` |
  | `plugins: [oidcPlugin(options)]`      | `const auth = oidcBearer(options)` from `@hyapi/plugin-oidc`  |
  | `auth: {}`                            | `guards: [auth]`                                              |
  | `auth: { scopes: ["a"] }`             | `guards: [auth, requireScopes("a")]`                          |
  | `auth: { required: false }`           | `guards: [jwtBearer({ secret, optional: true })]`             |
  | `auth: false` under a protected group | Move the route out of the guarded group                       |
  | `platform.setAuthProvider(provider)`  | `defineGuard({ name, check: ({ request }) => identity })`     |

  Guards run before body parsing and validation, so a guarded route answers an unauthenticated
  request with 401 even when its body is invalid. Custom identities must add `claims` (use `{}` when
  there are none). A custom 401 needs `new UnauthorizedError(message, { challenge })` to send
  `www-authenticate`. OpenAPI security schemes now come only from guards.
- **Modules implement Ports during setup.** Change `provides: [providePort(port, value)]` to
  `provides: [port]` and call `module.provide(port, () => value)` in `setup`. Factories may resolve
  the module's singletons. Application-level `providers` are unchanged.
- **Request state is typed.** Replace `state.set("key", value)` and `state.get("key") as T` with a
  module-level `const key = defineStateKey<T>("key")` and `state.set(key, value)` /
  `state.get(key)`.
- **Problem types.** `type` is `about:blank` by default. Set
  `defineConfig({ problemTypeBaseUrl: "https://errors.example.com" })` to keep code-specific URIs.
- **Responses are type-checked.** On routes that declare `responses`, `ok`, `created`, `json`,
  `noContent`, and bare return values must match a declared status and schema. Fix each compile
  error at its source; it previously surfaced as a runtime 500. Pass non-literal objects when a
  domain value carries extra properties; runtime validation still strips them. Wrap routes defined
  in their own files with `defineRoute()`.
- **`environment` defaults to `production`.** Set `environment: "development"` explicitly to see
  internal error messages and details in problem responses during development.
- **`DELETE` with a body returns 200.** Handlers that relied on the previous 500 have none to rely
  on; set `responseStatus` to choose another status.
- **New, optional:** `Module.config` with `createApplication({ moduleConfig })`,
  `module.healthCheck()`, `module.health()`, `module.liveness()`, `app.liveness()`, and `serve()`.
  Replace hand-written `Deno.serve` shutdown code with
  `serve(app, { shutdownSignals: ["SIGINT", "SIGTERM"] })`.

## Migrating from v1.0.0-rc.2 to v1.0.0-rc.3

This candidate changes lifecycle and request-scope behavior. Update code that assumes it can resolve
services after a request or application closes, that hooks can finish after the request deadline, or
that the application keeps accepting requests while shutting down.

- **Closed scopes reject resolution.** Resolving a request-scoped service after its request ends, or
  a singleton after `app.close()`, rejects with `AppError` code `SCOPE_CLOSED`. Services created
  after their scope closes are closed immediately; request cleanup errors reach `onError` without
  replacing the response.
- **Shutdown has separate drain and cleanup budgets.** `app.close()` rejects new requests with 503
  `APPLICATION_UNAVAILABLE`, drains in-flight work up to `shutdownTimeoutMs` (default 30000 ms),
  aborts remaining `ctx.signal`s, then allows at most `min(1000, shutdownTimeoutMs)` for cooperative
  cleanup. Module/plugin hooks, singletons, and providers share a separate `shutdownTimeoutMs`
  budget. Uncooperative handlers may outlive resource closure. `app.health()` returns
  `{ status: "unhealthy", checks: [] }` after close without running health checks. Set
  `defineConfig({ shutdownTimeoutMs })` to change the budgets.
- **Request timeout includes global hooks.** The existing `requestTimeoutMs` budget starts before
  global `onRequest` hooks; `ctx.signal` also aborts if the client disconnects.
- **Response hooks continue outward on failure.** When an `onResponse` hook throws, its problem
  response replaces the response and remaining outer hooks still run.
- **Error hooks observe within the deadline.** Matched-route group `onError` hooks run before global
  hooks, each seeing the original failure even if an earlier hook changes `lifecycle.error`.
  Asynchronous observers are awaited only until the original request deadline or forced shutdown;
  cleanup notifications after request end use the remaining original deadline. Abandoned observers
  may continue or mutate shared state later; their completion is not guaranteed, and they cannot
  replace the selected HTTP failure.
- **Startup cleanup is bounded.** Rollback closes set-up modules/plugins in reverse order on the
  shared `shutdownTimeoutMs` deadline. Provider startup failures flatten nested rollback errors in
  order, with the original connect exception first and its cause chain preserved. The startup
  aggregate retains the failed stage as its `cause`; without further application cleanup errors, the
  provider aggregate is propagated directly.
- **Stream ownership is explicit.** Body-schema routes buffer bounded content once so handler and
  hooks can each read it; early errors and schema-less streams cannot be replayed. Native response
  streams are caller-owned after the request returns; `pull`/`cancel` must not access request
  services, providers, singletons, or `ctx.signal` after return. Transport errors after response
  commitment cannot become problem+json. See [ADR 0001](../decisions/0001-layered-error-scopes.md).
- **HTTP retry backoff is cancellable.** Aborting the caller's `signal` during a retry delay rejects
  immediately with reason `"aborted"`.
- **Optional HTTP request bodies can be omitted.** If a contract route declares
  `request: { body: schema, bodyRequired: false }`, the typed client accepts a call without `body`
  and sends no request body. Routes without `bodyRequired: false` still require their declared body.

## Migrating to v1.0.0-rc.2

rc.2 fixes the issues found in the rc.1 audit. Following the pre-1.0 policy, superseded APIs are
removed outright: there are no deprecated aliases or transition periods. Each breaking change is
listed below with its replacement.

### Removed APIs

- **Hono `raw` removed.** `RequestContext.raw` and `LifecycleContext.raw` no longer exist. Read the
  standard `ctx.request`, `ctx.headers`, `ctx.params`, `ctx.query`, and `ctx.body` instead; Hono is
  not part of the public API.
- **Plugins receive `PlatformApi`.** `setup`, `onStart`, and `onClose` receive a frozen object with
  only `addHook(point, hook)` and `setAuthProvider(provider)`. Plugins can no longer register routes
  or reach the application instance; move route registration into a module.
- **`createTestApplication` removed.** Use `createApplication` and pass test doubles through
  `overrides`:

  ```ts
  // Before
  const app = await createTestApplication({ config, modules, overrides });
  // After
  const app = await createApplication({ config, modules, overrides });
  ```

- **Typed HTTP contract clients removed.** `provideHttp()` now passes a small native-fetch client to
  the adapter. The adapter explicitly selects paths and maps native `Response` values to its Port:

  ```ts
  provideHttp(port, {
    contract,
    baseUrl,
    adapt: (client) => ({
      async find(id) {
        const response = await client.fetch(`/v1/items/${encodeURIComponent(id)}`);
        if (!response.ok) throw new Error(`Items service returned ${response.status}.`);
        return await response.json();
      },
    }),
  });
  ```

- **Numeric versions, `PortVersion`, and `normalizeContractVersion` removed.** `Port.version` and
  `HttpContract.version` are `ContractVersion` objects. Rewrite `1` as `{ major: 1, minor: 0 }`.
  `definePort(id)` still defaults to `{ major: 1, minor: 0 }`. Versions whose `major` or `minor` is
  not a non-negative integer throw `ConfigurationError`.

### Routing, hooks, and auth

- **Auth scopes are a union.** A route inside a group requires the group's scopes and its own. A
  group with `users:read` and a route with `users:write` now requires both.
- **Inherited auth cannot be downgraded.** Inside an authenticated group, a route or nested group
  with `auth: false` or `auth: { required: false }` throws `ConfigurationError` at registration.
- **`onResponse` hooks use onion order.** Order is global `onRequest`, group `onRequest` (outer to
  inner), handler, group `onResponse` (inner to outer), global `onResponse`. Error responses also
  pass through group and global `onError`/`onResponse` hooks for matched routes. An unmatched 404
  skips `onError` but still runs global `onResponse`.
- **Registration is locked after start.** Calling `addHook`, `route`, or `setAuthProvider` after
  `createApplication()` resolves throws `ConfigurationError`. Register everything during `setup`.
  Hooks added to a group after its routes are registered still apply to those routes.
- **GET routes cannot declare a request body.** A route that conflicts with the OpenAPI document
  path also throws `ConfigurationError`.
- **Statically mismatched path schemas fail at registration.** For `Type.Object` parameter schemas,
  a required property without a default must name a parameter in the full route path, including
  group prefixes. For example, `/orders/{orderId}` with required `id` throws `ConfigurationError`.
  Routes without a params schema and dynamic schemas remain unchanged.
- **Route matching follows registration order.** Register a static route such as `GET /users/me`
  before `GET /users/{id}`. Reversing them can route `/users/me` through the parameter route's auth,
  hooks, handler, and status instead.

### Modules and services

- **`module.use(port)` requires a declaration.** A module must list the port in `requires`;
  otherwise `use` throws `ConfigurationError`.
- **Singletons cannot depend on request services.** A singleton factory always receives the
  application-level resolver; resolving a request-scoped service from it fails. A factory that
  throws is no longer cached, so the next resolution retries.
- **Startup rollback.** If a plugin or module fails during startup, already set-up modules and
  plugins are closed in reverse order.

### Request pipeline

- **Body limit.** Request bodies are limited to 10 MiB by default. Larger bodies are rejected with
  413 `PAYLOAD_TOO_LARGE`. Configure with `defineConfig({ bodyLimitBytes })`.
- **Request timeout.** Every request has a budget of `requestTimeoutMs` (default 300000 ms, 5
  minutes). When it expires, `ctx.signal` is aborted and the client receives 503 `REQUEST_TIMEOUT`.
- **`ctx.deadline` is required and `ctx.signal` is new.** `ctx.deadline` is always the earlier of
  the upstream `x-hyapi-deadline` and the request start plus `requestTimeoutMs`. Pass `ctx.signal`
  to long-running work.
- **Expired upstream deadlines return 504.** A request whose `x-hyapi-deadline` has already passed
  is rejected with 504 `DEADLINE_EXCEEDED` before the handler runs. Malformed deadline headers are
  ignored.
- **Header schema names follow HTTP case-insensitivity.** A declared `X-Tenant-Id` property
  validates an incoming `x-tenant-id` header without changing the schema or source request.
  Declaring both spellings in one object schema is ambiguous and throws `ConfigurationError`.
- **Framework-serialized responses drop undeclared fields.** Helper results (`ok(...)`,
  `respond(...)`, etc.) and bare return values are cleaned against declared response schemas before
  validation, so fields such as `passwordHash` are not serialized. These response payloads are
  runtime-validated, not statically checked against the schema by TypeScript. A native `Response` is
  an opaque body escape hatch: declared status is checked, but the body is neither cleaned nor
  validated. `Response.json({ id, passwordHash })` can therefore expose `passwordHash` even if only
  `id` is declared; use `ok(...)` for schema-enforced JSON.
- **Declared error statuses include both response formats in OpenAPI.** For a declared 4xx/5xx
  status, the document includes `application/json` for a framework-serialized body and
  `application/problem+json` for a thrown `AppError`; this does not add speculative statuses or
  change native `Response` handling.
- **`SyntaxError` is no longer mapped to 400.** Invalid request JSON still returns 400
  `INVALID_JSON`; a `SyntaxError` thrown by a handler returns 500.

### HTTP clients

- **`createHttpContractClient()` and `HttpContractClientError` are removed.**
- **`createHttpClient({ baseUrl })` preserves base URL paths and returns a native `Response`.** It
  passes the supplied `RequestInit` to Deno `fetch` without status mapping, response validation,
  retry, timeout, or deadline policy.
- **Adapters own outbound behavior.** They decide how to parse statuses and bodies, pass
  cancellation signals, and apply resilience only to operations that need it.

### JWT

- **Secrets are measured in bytes.** `jwtPlugin` requires a cryptographically random secret of at
  least 32 UTF-8 bytes.
- Tokens with a `crit` header, malformed compact encoding, a missing or non-finite `exp`, or a
  non-finite `nbf` are rejected with the same 401 response. A negative `clockSkewSeconds` throws
  `ConfigurationError`.

## Current HTTP boundary

The current HTTP boundary breaks the old typed-client API but keeps modules, Ports, server-side HTTP
contracts, and resilience policies independent. Update remote adapters to use `client.fetch()`.

### Runtime hardening

- `withHttpContext()` forwards the request deadline header. Outbound adapters pass their chosen
  `AbortSignal` through `RequestInit`; the client does not impose a second deadline.
- Bulkhead waiters are admitted FIFO. A full queue still fails with `ResilienceError` using the
  `bulkhead_rejected` reason.
- Resilience state belongs to the adapter operation. Circuit breakers count provider failures while
  errors marked as client, contract, validation, business, deadline, or aborted do not.
- Resilience policies reject invalid values early.

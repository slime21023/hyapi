# Migrating to v0.9.0

v0.9 adds explicit resilience policies for operations that need them. The policy is independent of
the HTTP client: apply `withResilience()` to a Port-adapter operation and keep the native client
responsible only for transport.

```ts
const findUser = withResilience(
  async (id: string) => {
    const response = await client.fetch(`/v1/users/${encodeURIComponent(id)}`);
    if (!response.ok) throw new Error(`Users service returned ${response.status}.`);
    return await response.json();
  },
  {
    retry: { maxAttempts: 3, initialDelayMs: 25, backoff: "exponential", jitter: true },
    circuitBreaker: { failureThreshold: 5, resetTimeoutMs: 10_000 },
    bulkhead: { maxConcurrent: 32, queueSize: 64 },
  },
);
```

Choose retry conditions in the adapter, especially for non-idempotent operations. Resilience
failures are classified as `timeout`, `circuit_open`, or `bulkhead_rejected` and preserve their
original cause where available.

# Migrate to HyAPI v0.2

HyAPI v0.2 replaces application registration with a function-first composition model. Route schemas,
response helpers, RFC 7807 errors, OpenAPI output, and `app.request()` behavior remain unchanged.

## Breaking changes

| v0.1 API                             | v0.2 replacement                                            |
| ------------------------------------ | ----------------------------------------------------------- |
| `createApp({ config })`              | `await createApplication({ config, modules, plugins })`     |
| `app.register(plugin, options)`      | `plugins: [plugin(options)]` in `createApplication`         |
| `Plugin.register(app, options)`      | `definePlugin({ setup(platform) })`                         |
| `PluginApi`                          | `PlatformApi`; it deliberately does not expose Hono         |
| `app.decorate()` / `getDecoration()` | module service reference plus `context.services.get()`      |
| root `app.route()` / `app.group()`   | register routes from `defineModule({ setup(module) })`      |
| `await app.ready()`                  | `createApplication()` resolves only after startup completes |

`createApp`, `HyApiApp`, `RouterGroup`, `PluginApi`, and legacy registration types are no longer
exported by `@hyapi/core`.

## Before

```ts
const app = createApp({ config });
await app.register(jwtPlugin(), { secret });

const repository = new UserRepository();
const service = new UserService(repository);
app.group("/v1/users", (users) => {
  users.route(listUsersRoute(service));
});

await app.ready();
```

## After

```ts
const usersModule = defineModule({
  name: "users",
  setup(module) {
    const repository = module.singleton(() => new UserRepository());
    const service = module.request(async (services) => {
      return new UserService(await services.get(repository));
    });

    module.group("/v1/users", (users) => {
      users.route(listUsersRoute(service));
    });
  },
});

const app = await createApplication({
  config,
  modules: [usersModule],
  plugins: [jwtPlugin({ secret })],
});
```

Change a route that uses a service reference to resolve it from request context:

```ts
const listUsersRoute = (service: ServiceReference<UserService>) =>
  defineRoute({
    method: "get",
    path: "",
    handler: async ({ services, ok }) => ok(await (await services.get(service)).list()),
  });
```

## Lifecycle and scopes

- Plugins run their `setup` hooks before modules; plugin dependencies determine their order.
- Modules run `setup` and `onStart` in import order; `onClose` runs in reverse order.
- `singleton` values are shared until application close.
- `request` values are shared only within one request and closed after response hooks.
- `transient` values are newly created for every `services.get()` call; their cleanup remains
  caller-owned.

Call `await app.close()` during server shutdown. Closing is idempotent.

## Tests and service overrides

Pass `overrides` to `createApplication()` with named service references to replace external
dependencies before the application starts:

```ts
const clock = module.singleton("clock", () => productionClock());

const app = await createApplication({
  config,
  modules: [module],
  overrides: [provideValue("clock", fakeClock)],
});
```

The production factory is not invoked when an override with the same name is present.

## Migration checklist

1. Replace the root application factory and remove `app.ready()`.
2. Move each business feature's routes and local services into one Module.
3. Convert authentication, logging, and other cross-cutting concerns to Plugins.
4. Replace decorations with typed service references.
5. Update tests to construct applications through `createApplication`.
6. Run `deno task verify` before upgrading production deployments.

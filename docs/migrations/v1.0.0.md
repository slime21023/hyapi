# Migrating to v1.0.0-rc.1

The release candidate keeps the v0.9 public API. Existing modules, Ports, providers, HTTP contracts,
and resilience policies continue to compile without changes.

## Runtime hardening

- HTTP clients now honor the smaller of `HttpContractClientOptions.deadline` and the propagated
  `x-hyapi-deadline` header. Retries stop when that absolute millisecond deadline is reached.
- HTTP request timers are cleared after completion, and timed-out fetches receive an abort signal.
- Bulkhead waiters are admitted FIFO. A full queue still fails with `ResilienceError` using the
  `bulkhead_rejected` reason.
- A configured HTTP client's circuit-breaker and bulkhead state is retained across calls, so one
  client should represent one remote dependency boundary.
- Circuit breakers count transient/provider failures, while client and contract failures do not
  consume the failure threshold.
- Resilience policies and configured client deadlines reject non-finite or invalid values early.

## RC verification

Run the release gate from a clean checkout:

```text
deno task verify
git diff --check
```

After this candidate, only test coverage, performance/security regression evidence, and
documentation/example fixes are in scope for the `v1.0.0` release.

# Migrating to v0.9.0

v0.9 adds explicit resilience policies for remote operations. Existing HTTP clients keep their v0.8
behavior when no `resilience` policy is provided.

```ts
const resilientClient = createHttpContractClient(contract, {
  baseUrl: "http://users-service",
  timeoutMs: 1000,
  resilience: {
    retry: { maxAttempts: 3, initialDelayMs: 25, backoff: "exponential", jitter: true },
    circuitBreaker: { failureThreshold: 5, resetTimeoutMs: 10_000 },
    bulkhead: { maxConcurrent: 32, queueSize: 64 },
  },
});
```

Safe HTTP methods use retry policies explicitly configured for the operation. Non-idempotent calls
should provide an idempotency key before enabling retries. Resilience failures are classified as
`timeout`, `circuit_open`, or `bulkhead_rejected` and preserve their original cause where available.

The v1.0.0 release candidate additionally enforces propagated `x-hyapi-deadline` values across
remote retries and admits bulkhead waiters in FIFO order; see the
[v1.0.0 candidate guide](v1.0.0.md).
